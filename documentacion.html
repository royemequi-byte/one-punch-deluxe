01

El juego

ONE PUNCH DELUXE es un videojuego de boxeo 2D arcade estilo KOF (King of Fighters) — vista lateral con los dos personajes enfrentados — desarrollado en Unity 6 como trabajo de grado universitario. El jugador controla a Wally, un boxeador con historia propia, contra el rival Máximo / Kirikú en un ring profesional con multitud animada.

El juego cuenta con modo historia completo (paneles de arte manga con narrativa), sistema de combate con tres golpes + esquives + bloqueo, HUD con barra de vida y stamina, sistema de rounds, pantalla de game over, guardado en JSON y soporte para mando Xbox.

IA de Kirikú — FSM de 7 estados

RivalAI.cs carga KirikuProfile.asset y ejecuta una máquina de estados: Idle → Telegraph → Attack → Recovery → Idle, con bifurcaciones a Block, Dodge y Stunned. El estado Telegraph (0.25s) es visible para el jugador — la animación kiriku_telegraph.png aparece antes de cada golpe fuerte, dando una ventana de esquive.

Python — Pipeline de arte

Python se usó exclusivamente como herramienta de producción de assets en Tools/. Regla del proyecto: "C# ejecuta el juego, Python prepara lo que C# consume."

Scripts implementados

remove_bg.py
Usa rembg (IA) para eliminar el fondo. Guarda _transparent.png junto al original.
batch_normalize.py
Separa frames, alinea pies al mismo nivel base, centra en celda uniforme y exporta sprite sheet listo para Unity.
normalizar_kiriku.py
Detecta filas con contenido via canal alpha, recorta y escala a 353px de alto. No toca sprites que ya tienen ≥98% del alto.
generar_ring.py
Genera el ring 1920×1080 programáticamente: gradiente oscuro de arena, 350 siluetas de multitud, focos y cuerdas.
make_transparent.py
Convierte fondo de color sólido a transparente (alpha=0) para sprites que no pasaron por rembg.
procesar_wally.py / procesar_kiriku.py
Pipeline completo por personaje: remove_bg → normalizar → corregir → exportar a su carpeta en Assets/.
fix_wally_ghosts.py
Elimina píxeles fantasma (artefactos semitransparentes) que dejaba rembg en los bordes del sprite.
organizar_sprites.py
Mueve y renombra sprites procesados a las carpetas correctas de Assets/Art/Personajes/.

Scripts C# principales

ScriptResponsabilidadNota clave
FightManager.cs Posiciona personajes al iniciar el combate Wally (-3,-1.5) · Kiriku (3,-1.5) con escala y flip correctos
HUDController.cs Barras de vida, stamina, timer, controles en pantalla BuscarGO() tolera espacios al inicio del nombre del GO
RivalAI.cs FSM de 7 estados para el comportamiento de Kirikú Lee KirikuProfile.asset — agresividad y patrones configurables
AudioManager.cs Reproduce música y SFX con pool de fuentes Singleton null-safe con ?. · usa AudioMixer con dB correcto
SaveManager.cs Guarda y carga progreso con JsonUtility Singleton null-safe
GameManager.cs Flujo general: escenas, estados, rounds Singleton null-safe · gestiona transición entre pantallas
VisualJuice.cs Efectos de cámara y ring CrearFondoRing() fija escala a 0.926 · pendiente de integrar en escena
Patrón null-safe: todos los Managers usan ?. para que su ausencia en escena no genere NullReferenceException. El juego no crashea si un sistema está en desarrollo.

¿Por qué Git LFS? Los PNG y WAV de Unity pueden superar el límite de 100 MB de GitHub. Git LFS reemplaza esos archivos por punteros ligeros y almacena el contenido real aparte, manteniendo el historial ágil.
